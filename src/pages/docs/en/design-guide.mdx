# Design Guide

<div class="doc-intro">
  <p>This guide walks through the five-step process of turning a mockup into a working <code>baseConfig</code> — from reading the layout to encoding every style rule correctly.</p>
</div>

## Overview

Every card grid in Astro Micro starts from a `baseConfig` object. The goal of this guide is to help you translate a visual mockup or design spec into an accurate config without guessing.

---

## Step 1 — Layout Analysis

Look at your mockup and answer these questions:

**How many columns are there?**
- Single column → `list: true` or `tiers: [{ cols: 1, minWidth: 0 }]`
- Multiple columns → define a `tiers[]` array

**Does column count change at breakpoints?**
- Yes → add multiple tiers (e.g. 1 col on mobile, 2 on tablet, 4 on desktop)
- No → single tier is enough

**Are card heights uniform?**
- Yes → standard grid layout
- No → consider `masonry: true`

**Are there labeled groups?**
- Yes (e.g. "Featured" vs "Regular") → define `groups[]`

---

## Step 2 — Pick a Render Mode

```
Does the grid have uniform row height?
  ├─ Yes → standard grid
  └─ No  → masonry: true

Is there only one column?
  └─ Yes → list: true (cleaner semantics)

Are cards grouped into named sections?
  └─ Yes → define groups[] in config
```

---

## Step 3 — Define Tiers

Map each design breakpoint to a tier:

```js
tiers: [
  { cols: 1, minWidth: 0 },     // mobile: 1 column
  { cols: 2, minWidth: 640 },   // tablet: 2 columns
  { cols: 4, minWidth: 1024 },  // desktop: 4 columns
],
```

Tiers are evaluated from widest to narrowest; the first matching tier is applied. Breakpoints loosely match Tailwind's: `sm = 640px`, `md = 768px`, `lg = 1024px`, `xl = 1280px`.

---

## Step 4 — Build makes[]

Each `makes` entry maps one visual element in the card to one data field.

Read each element from the mockup top to bottom:
1. What is the element? (image, text, price, badge, rating, button)
2. Which data field does it display?
3. Are there any visual styles? (size, weight, color, aspect ratio)

```js
makes: [
  // Product image — fill width, fixed 4:3 ratio
  {
    opt: 'image',
    val: 'thumbnail',
    stys: { aspectRatio: '4/3', width: '100%', objectFit: 'cover' },
  },

  // Product name — bold, 1rem
  {
    opt: 'text',
    val: 'name',
    stys: { fontWeight: '600', fontSize: '1rem' },
  },

  // Category tag — subdued color
  {
    opt: 'text',
    val: 'category',
    stys: { fontSize: '0.75rem', color: 'var(--color-base-content)', opacity: '0.6' },
  },

  // Price — accent color, larger
  {
    opt: 'price',
    val: 'price',
    stys: { color: 'var(--color-primary)', fontWeight: '700' },
  },
],
```

---

## Step 5 — Color Rules

> **Only use CSS variables. Never hardcode hex, rgb, or hsl values.**

This is the most commonly broken rule. Every color in your config must reference a CSS variable:

```js
// Correct
{ stys: { color: 'var(--color-primary)' } }
{ stys: { background: 'var(--color-base-200)' } }
{ stys: { borderColor: 'var(--color-base-300)' } }

// Wrong — breaks dark mode, custom themes
{ stys: { color: '#3b82f6' } }
{ stys: { background: 'rgb(249, 250, 251)' } }
```

Available variables: `--color-primary`, `--color-secondary`, `--color-base-100/200/300`, `--color-base-content`, `--color-error`, `--color-warning`, `--color-success`, `--color-info`.

## Complete Product Card Example

```js
// src/sections/shop/config.js

export const productConfig = {
  id: 'shop-products',

  // Responsive columns
  tiers: [
    { cols: 1, minWidth: 0 },
    { cols: 2, minWidth: 640 },
    { cols: 4, minWidth: 1024 },
  ],

  // Card entrance animation
  anime: 'fade-up',
  animeQueue: { delay: 60, max: 8 },

  // Card-level style
  groupStyle: {
    background: 'var(--color-base-100)',
    borderRadius: 'var(--radius-box)',
    overflow: 'hidden',
    boxShadow: '0 1px 3px color-mix(in sRGB, var(--color-base-content) 10%, transparent)',
  },

  // Cell definitions
  makes: [
    {
      opt: 'image',
      val: 'thumbnail',
      stys: { aspectRatio: '4/3', width: '100%', objectFit: 'cover' },
    },
    {
      opt: 'text',
      val: 'name',
      stys: { fontWeight: '600', fontSize: '1rem', padding: '0.5rem 0.75rem 0' },
    },
    {
      opt: 'text',
      val: 'category',
      stys: {
        fontSize: '0.75rem',
        color: 'var(--color-base-content)',
        opacity: '0.6',
        padding: '0 0.75rem',
      },
    },
    {
      opt: 'price',
      val: 'price',
      stys: {
        color: 'var(--color-primary)',
        fontWeight: '700',
        padding: '0.25rem 0.75rem 0.75rem',
      },
    },
  ],
};
```

## Common Mistakes

| Mistake | Fix |
|---|---|
| Hardcoded hex color in `sty` | Replace with `var(--color-*)` |
| Single tier for a multi-breakpoint design | Add tiers for each breakpoint |
| Using `px` font sizes that ignore user preferences | Prefer `rem` |
| Forgetting `objectFit: 'cover'` on images | Images stretch — always set `objectFit` for image cells |
| Putting all cells in one `makes[]` when the design has groups | Split into `groups[]` |
